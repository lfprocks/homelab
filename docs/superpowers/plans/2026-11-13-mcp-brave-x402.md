# mcp-brave-x402 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go MCP server that gives Hermes Brave web, news and LLM-context search. It pays Brave's x402 proxy per call from a hot wallet only it holds, under a daily cap, and exports spend and balance metrics. It is deployed on the-intersect and wired into Hermes.

**Architecture:**
- **Server:** a copy of the `lfpweather-mcp` layout (mcp-go streamable HTTP, ootel metrics, caarlos0/env config) plus three new packages:
  - `internal/budget`: daily reservation ledger
  - `internal/brave`: drives the x402 handshake by hand, so the offer is checked and budget reserved *before* signing, and also trims results
  - `internal/wallet`: USDC balance poller
- **Homelab:** the server is deployed as `apps/mcp-brave-x402` modelled on `apps/mcp-wsdot`, and Hermes reaches it over an in-cluster Service with a bearer token.

**Tech Stack:**
- Go 1.26, `github.com/x402-foundation/x402/go/v2` v2.31.0, `github.com/mark3labs/mcp-go`, `alpineworks.io/ootel`, `github.com/caarlos0/env/v11`, OpenTelemetry metric API
- Forgejo Actions with remote BuildKit
- Flux, Kustomize, SOPS, Cilium, Grafana alerting

## Review Focus

1. **Concurrent calls at the cap edge:** with 1 unit of headroom left, 20 concurrent searches must produce at most one payment. Covered by a test in Task 2.
2. **Challenge with several `accepts` entries, one valid:** pay only the matching entry. If none match, refuse with no signature and no reservation. Covered by a test in Task 3.
3. **Proxy returns 2xx with no `PAYMENT-RESPONSE` header, or a 502 after the signature was sent:** count it as spent, since money may have moved. A 4xx after signing releases the reservation. Covered by tests in Task 3.
4. **Day rollover:** a reservation made at 23:59:59 Pacific must not be credited against the next day. A DST-change day still resets once at local midnight. Covered by a test in Task 2.
5. **RPC returns garbage or errors:** the balance gauge keeps its last value and the last-success timestamp does not advance, so the stale alert fires. Covered by a test in Task 5.

### Task 3: Offer check and paying client

**Files:**
- Create: `internal/brave/offer.go`, `internal/brave/client.go`, `internal/brave/offer_test.go`, `internal/brave/client_test.go`

**Interfaces:**
- Consumes: `budget.Budget` and `budget.ErrExceeded` from Task 2.
- Produces:
  ```go
  type Allowlist struct{ Scheme, Network, Asset, PayTo string; MaxUnits int64 }
  var ErrOfferRefused = errors.New("payment offer refused") // wrapped with the reason
  func SelectOffer(pr types.PaymentRequired, a Allowlist) (types.PaymentRequirements, int64, error)

  type Endpoint string
  const (EndpointWeb Endpoint = "/res/v1/web/search"; EndpointNews = "/res/v1/news/search"; EndpointLLMContext = "/res/v1/llm/context")

  type Outcome string // "paid","refused_cap","refused_offer","upstream_error","payment_error"
  type Recorder interface{ Record(ctx context.Context, ep Endpoint, o Outcome, units int64) }

  type Client struct{ /* baseURL, http *http.Client, x402 payload creator, allow Allowlist, budget *budget.Budget, rec Recorder */ }
  func NewClient(baseURL string, httpClient *http.Client, privateKeyHex string, allow Allowlist, b *budget.Budget, rec Recorder) (*Client, error)
  func (c *Client) Get(ctx context.Context, ep Endpoint, q url.Values) ([]byte, error)
  var ErrUpstream = errors.New("brave upstream error") // wrapped with status
  ```
  - `types` is `github.com/x402-foundation/x402/go/v2/types`.
  - `NewClient` builds the signer with `evmsigners.NewClientSignerFromPrivateKey`, and the payload creator with `x402.Newx402Client().Register("eip155:8453", evm.NewExactEvmScheme(signer, nil))`.
  - The client must not be wrapped with `x402http.WrapHTTPClientWithPayment`, because that would sign before our checks.
  - `NewClient` errors must not include the key.

**Handshake in `Get`, in order:**
1. GET `baseURL+ep+"?"+q.Encode()` with no payment header.
   - If the response is not a 402, return its body when it's 2xx, otherwise `ErrUpstream`, without spending anything.
2. Read the `PAYMENT-REQUIRED` header, base64-decode it, and JSON-decode it into `types.PaymentRequired`.
   - If `X402Version != 2`, or the header is missing or malformed, return `ErrOfferRefused`.
3. Call `SelectOffer`. It picks the first `accepts` entry where scheme, network, asset and payTo match (asset and payTo case-insensitive) and the amount parses as `int64` with `0 < amount ≤ MaxUnits`.
   - On failure: `rec.Record(refused_offer)`, return `ErrOfferRefused`.
4. Call `budget.Reserve(amount)`.
   - On `ErrExceeded`: `rec.Record(refused_cap)`, return it.
5. Call `CreatePaymentPayload(ctx, req, pr.Resource, pr.Extensions)`, `json.Marshal` the result, base64 it, and set the `PAYMENT-SIGNATURE` header. Resend the identical GET.
   - On a signing error: `Release`, `rec.Record(payment_error)`.
6. Handle the paid response:
   - **2xx:** `Commit`, `rec.Record(paid, amount)`, return the body. Log the decoded `PAYMENT-RESPONSE` `Transaction` at info level when present. Commit even if the header is missing.
   - **502, or a transport error after sending:** `Commit`, `rec.Record(upstream_error, amount)`, return `ErrUpstream`.
   - **Anything else (a second 402, or 4xx):** `Release`, `rec.Record(payment_error, 0)`, return `ErrUpstream` with the status.
